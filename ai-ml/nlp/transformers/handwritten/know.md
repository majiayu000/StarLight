# 基础知识

## 词向量
计算机不能直接理解文字，需要把文字转换成数字。

```
"我" → [0.1, 0.3, 0.8, 0.2]  (4维向量)
"爱" → [0.5, 0.1, 0.2, 0.9]  
"你" → [0.8, 0.7, 0.1, 0.4]
```

### 维度
一维的问题：
如果每个词只用一个数字表示：
```
"我" → 1
"爱" → 2  
"你" → 3
"苹果" → 4
```
**问题：**
- 无法表达词的复杂含义
- "我"和"你"都是人称代词，但数字1和3没有体现这种相似性
- 无法表达词之间的语义关系

### 多维向量的优势
每个维度可以表示不同的"语义特征"：
```python
# 假设4维向量，每个维度有特定含义：
# [情感程度, 是否为名词, 是否为人, 抽象程度]

"我"     → [0.1, 0.0, 1.0, 0.2]  # 中性情感，不是名词，是人，具体
"爱"     → [0.9, 0.0, 0.0, 0.8]  # 强烈情感，不是名词，不是人，抽象  
"苹果"   → [0.2, 1.0, 0.0, 0.1]  # 轻微情感，是名词，不是人，具体
"快乐"   → [0.9, 0.3, 0.0, 0.9]  # 强烈情感，偏名词，不是人，抽象
```

### 实际中的维度
#### 现实中的词向量：
- Word2Vec: 通常100-300维
- BERT: 768维
- GPT: 可能1024维或更高


### 维度是怎么来的
1. 随机初始化
开始时，每个词的768维向量都是随机数：
```python
"我" → [0.23, -0.45, 0.67, 0.12, ..., 0.89]  # 768个随机数
"爱" → [-0.34, 0.78, -0.23, 0.56, ..., -0.12] # 768个随机数
```
2. 通过训练自动学习
模型在大量文本上训练时：
- 如果两个词经常出现在相似的上下文中，它们的向量会变得相似
- 如果两个词很少一起出现，向量会变得不同
- 每个维度的值会自动调整
3. 没有明确的含义分工
训练完成后：
- 第1维可能部分表示情感，部分表示词性，部分表示其他特征
- 第2维可能是完全不同的特征组合
- 每个维度都是多种语义特征的混合

### 为什么是768？
#### 经验和实验结果：
- 不是理论推导出来的
- 是研究者通过大量实验发现的"好用"的数字
- 在计算效率和表达能力之间的平衡
####其他常见维度：
- GPT-1: 768维
- GPT-2: 768/1024/1536维（不同版本）
- GPT-3: 12288维
- BERT-base: 768维
- BERT-large: 1024维

### QKV的维度设计
#### 以BERT为例
```python
# 输入
d_model = 768      # 输入词向量的维度
seq_len = 128      # 序列长度（句子中词的个数）
batch_size = 32    # 批次大小

# 输入矩阵 X 的形状
X: (batch_size, seq_len, d_model) = (32, 128, 768)
```
Q、K、V的维度通常设置为：
```python
d_k = d_v = 64     # Q和K的维度，V的维度

# 线性变换后的形状
Q: (batch_size, seq_len, d_k) = (32, 128, 64)
K: (batch_size, seq_len, d_k) = (32, 128, 64)  
V: (batch_size, seq_len, d_v) = (32, 128, 64)
```
#### X是什么？
X就是输入到Transformer的词向量矩阵，它是整个模型的起点。
##### X的构成
1. 原始输入
```
# 假设我们有一个句子
sentence = "我 爱 吃 苹果"
```

2. 转换过程
```
# 步骤1: 词汇表映射
"我" → token_id: 101
"爱" → token_id: 205  
"吃" → token_id: 308
"苹果" → token_id: 442

# 步骤2: 查找词向量表
embedding_table = {
    101: [0.1, 0.3, 0.8, ..., 0.2],  # 512维向量
    205: [0.5, 0.1, 0.2, ..., 0.9],  # 512维向量
    308: [0.8, 0.7, 0.1, ..., 0.4],  # 512维向量
    442: [0.2, 0.9, 0.5, ..., 0.7]   # 512维向量
}

# 步骤3: 组成矩阵X
X = [
    [0.1, 0.3, 0.8, ..., 0.2],  # "我"的512维向量
    [0.5, 0.1, 0.2, ..., 0.9],  # "爱"的512维向量  
    [0.8, 0.7, 0.1, ..., 0.4],  # "吃"的512维向量
    [0.2, 0.9, 0.5, ..., 0.7]   # "苹果"的512维向量
]
# X的形状: (4, 512) = (seq_len, d_model)
```
##### 批次处理
为什么有batch_size？
```python
# 实际训练时，我们同时处理多个句子：
batch = [
    "我 爱 吃 苹果",      # 句子1
    "你 喜欢 看 电影",    # 句子2
    "他 在 学习 编程",    # 句子3
    ...                  # 更多句子
]

# 每个句子都变成一个矩阵，然后堆叠：
X = torch.stack([
    sentence1_matrix,  # (128, 512)
    sentence2_matrix,  # (128, 512)
    sentence3_matrix,  # (128, 512)
    ...
])  
# 最终X的形状: (batch_size, seq_len, d_model) = (32, 128, 512)
```
X在Transformer中的流动
```python
# 1. 输入X
X: (32, 128, 512)

# 2. 线性变换得到Q、K、V
Q = X @ W_q  # (32, 128, 512) @ (512, 64) = (32, 128, 64)
K = X @ W_k  # (32, 128, 512) @ (512, 64) = (32, 128, 64)
V = X @ W_v  # (32, 128, 512) @ (512, 64) = (32, 128, 64)

# 3. 注意力计算
output = attention(Q, K, V)  # (32, 128, 64)
```
X就是：

把输入的文字转换成数字矩阵
每一行代表一个词的向量表示
这个矩阵是Transformer处理的"原材料"
比喻：

X就像是把一篇文章翻译成了"数学语言"
Transformer就是用数学运算来理解这篇"数学文章"



#### 为什么要降维？
1. **计算效率**：
```python
# 如果不降维，注意力矩阵的计算：
# Q×K^T: (128, 768) × (768, 128) = (128, 128)
# 计算量：128 × 768 × 128 = 12,582,912

# 降维后：
# Q×K^T: (128, 64) × (64, 128) = (128, 128)  
# 计算量：128 × 64 × 128 = 1,048,576
```
2. **表达能力**：
- 768维可以表达丰富的语义信息
- 64维仍然可以捕捉到重要的语义关系
- 降维后参数量减少，训练更高效

#### mask的作用
Mask用来"遮蔽"某些位置，让模型不要关注这些位置

两种常见的Mask：
1. Padding Mask（填充遮蔽）
```
    # 假设我们有两个句子，长度不同：
句子1: "我 爱 你"           # 3个词
句子2: "他 在 学习 编程"     # 4个词

# 为了批量处理，需要填充到相同长度：
句子1: "我 爱 你 <PAD>"     # 用<PAD>填充
句子2: "他 在 学习 编程"     # 不需要填充

# Padding Mask:
mask = [
    [0, 0, 0, 1],  # 句子1：前3个位置正常，第4个位置是填充
    [0, 0, 0, 0]   # 句子2：所有位置都正常
]
# 0表示正常位置，1表示需要遮蔽的位置
```
2. Look-ahead Mask（前瞻遮蔽）
```
# 在Decoder中，当前词不能看到未来的词
# 比如生成"我爱你"时：
# - 生成"我"时，不能看到"爱"和"你"
# - 生成"爱"时，不能看到"你"

mask = [
    [0, 1, 1],  # "我"只能看自己
    [0, 0, 1],  # "爱"能看"我"和自己，不能看"你"  
    [0, 0, 0]   # "你"能看所有前面的词
]
```

#### 为什么是 mask * -1e9？
数学原理：
```
# 假设注意力分数是：
scores = [
    [0.5, 0.3, 0.8],
    [0.2, 0.7, 0.4],
    [0.9, 0.1, 0.6]
]

# 如果mask是：
mask = [
    [0, 0, 1],  # 第3个位置需要遮蔽
    [0, 1, 1],  # 第2、3个位置需要遮蔽
    [0, 0, 0]   # 都不遮蔽
]

# 加上 mask * -1e9 后：
scores_masked = [
    [0.5, 0.3, 0.8 + (-1e9)],     # [0.5, 0.3, -1000000000]
    [0.2, 0.7 + (-1e9), 0.4 + (-1e9)], # [0.2, -1000000000, -1000000000]
    [0.9, 0.1, 0.6]                # [0.9, 0.1, 0.6]
]

# 然后应用softmax：
# softmax(-1000000000) ≈ 0
# 所以被遮蔽的位置注意力权重接近0

```

为什么不直接设为0？
```
# 如果直接设为0：
scores = [0.5, 0.3, 0.0]
softmax_result = [0.38, 0.32, 0.30]  # 0位置仍有30%权重！

# 如果设为-1e9：
scores = [0.5, 0.3, -1e9]
softmax_result = [0.55, 0.45, 0.00]  # 0位置权重真正为0！
```
